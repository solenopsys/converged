# Роли — это файлы

Роль в этом продукте не сущность, а пресет доступа: дерево грантов
`kind/service/method(mode)`, которое `rp-access` разворачивает в JWT. Таблицы
ролей, CRUD ролей и экрана редактирования ролей нет — правка роли это правка
файла из этого каталога и `bun run cli access preset seed`.

Разбор целиком — `../../../../team-contour.md` §1 и §3.

**Наследование делается линковкой, а не в файле.** `resolvePermissions`
объединяет все привязанные пользователю пресеты (`rp-access/src/service.ts:142`),
причём объединением: `r` и `w` на одном методе схлопываются в `rw`. Поэтому
каждый сотрудник носит `user` — базу кабинета — плюс ровно одну роль отсюда, а
в файле роли лежит только домен.

Вычитания при этом нет: «менеджер, но без отзывов» — это свой файл, а не
исключение в существующем.

**Два правила при правке:**

- звёздочка только осознанная. `"orders": "rw"` даёт и те методы, которые
  появятся завтра. Для `owner` это нормально, для `viewer` — нет;
- `wf` перечисляется поимённо. `wf/workflows/*(x)` — единственный грант, который
  превращается в право делать что угодно, потому что дальше идёт `SERVICE_TOKEN`.
